## Why
Links to the app (`/` and `/jobs/{id}`) show no preview card when shared, because crawlers do not run the SPA (junction-2026/project#48, child #57). The nginx container can add Open Graph and Twitter tags to the served `index.html` itself.

## What Changes
- nginx (njs module) answers HTML routes with the built `index.html` plus a card block in `<head>`: a generic site card, or for `/jobs/{id}[/detail|/live]` a verdict, in-progress or unavailable card based on `GET /api/v1/jobs/{id}`.
- New `nginx/og.js` (pure, njs-compatible render logic) and `nginx/og-handler.js` (njs entry point); six static 1200x630 images in `public/og/` generated by `scripts/og-images.py`.
- `PUBLIC_ORIGIN` env var (default `http://localhost`) prefixes every card URL.
- `index.html` carries the default card between `og:start`/`og:end` markers so `vite dev`/`preview` still render a valid head.
- `scripts/og-smoke.sh` checks the built image against a stub backend.
- No shared-spec change: the work only reads the existing public `GET /api/v1/jobs/{id}` (shared-specs analysis-jobs-api @ b4a04a191450549e9d263166bd8cc2904044cff6, see design).

## Impact
Specs: frontend-runtime (MODIFIED nginx behaviour, Multi-stage Dockerfile), new local capability link-preview-cards. Files: `index.html`, `Dockerfile`, `nginx/*`, `public/og/*`, `scripts/*`, README. The SPA body and assets are served unchanged.
